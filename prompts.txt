Stage 1 — product spec + architecture

You are a senior staff full-stack engineer. Rebuild the attached Python desktop app as a production-ready web application for 2026.

Goal:
Create a self-hosted anime backlog tracker that reproduces the desktop app’s behavior as a modern web app, optimized for Docker deployment.

Source behavior to preserve:
- Anime entity fields: id, name, year, season, status, type, comment, url, downloaded
- Status values: unwatched, watching, completed
- A dedicated “Pre-2010” section for entries with year < 2010
- Separate year views for year >= 2010, each split into seasons: winter, spring, summer, fall, other
- Search/filter by anime name
- CRUD operations for anime entries
- Quick actions: toggle status, toggle downloaded
- Import/export CSV
- Random pick from unwatched anime in the currently selected year/pre-2010 section
- Statistics view: total, completed, completion percentage, counts by type
- Shikimori info dialog equivalent: fetch anime metadata from Shikimori and cache it
- Persist basic UI preferences such as last selected view and table density / scale equivalent

Technical requirements:
- Frontend: Next.js App Router + TypeScript
- Backend API: FastAPI + Pydantic v2 + SQLModel or SQLAlchemy 2.0 typed ORM
- Database: PostgreSQL for production, SQLite allowed for local dev only
- Containerized with Docker and docker compose
- Clean architecture, type safety, accessibility, responsive layout, testability, secure defaults
- No inline mock data in final code
- Use server/client boundaries sensibly
- Use optimistic UI only where safe
- Avoid overengineering, but keep code modular and production-quality

Deliverables:
1. A concise architecture decision record
2. Monorepo folder structure
3. Database schema
4. API contract
5. Frontend route map
6. Component map
7. State management strategy
8. Error handling strategy
9. Docker/deployment plan
10. Step-by-step implementation plan

Important:
- Preserve feature parity with the desktop app, but redesign the UX for the web
